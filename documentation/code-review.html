    Findings

    F-1 (high): the renamed metrics break Mary’s surfaces. The mart design renamed or retired five release 1 metrics (face_amount_total, policies, policies_written, agents_writing, findings) and the entity client_policy. Mary’s release page tells her to ask for face_amount_total and for policies_held by client_policy__role, and the Ask page and QA retest carry the same names. After promotion she would be told to ask for metrics that no longer exist. Needed: the release page, the Ask page suggestions and the QA retest moved to the new names on their own branch, before QA’s consumer check (Ray, answer 1a).

    F-2 (closed 2026-11-01 07:40 UTC): the two saved queries resolve. q09_client_policies and q10_coverage_by_carrier group by Dimension(‘carrier__carrier_name’), two joins away through the policy. Compiled with MetricFlow 0.213.0, the connector’s own version, against the dev manifest, all six saved queries and the release page’s four prompts compile, and face_amount_current by carrier__carrier_name answers Northfield Life 125,000.00: MetricFlow finds the path itself. The same check found F-8.

    F-3 (medium): the full build did not run on freshly cloned data. The standard proves every change by a full build on a fresh clone; the developer landing clone was not refreshed first, and its vault was built over several sessions. The QA build on fresh clones closes this.

    F-4 (medium): Q-13’s answer shows a SYSTEM row. The one sale with no client number joins to the unknown client, whose source is SYSTEM and whose first-known day is empty, so the arrivals answer has a row Mary will not understand. Needed: the release answers explain it in her words.

    F-5 (medium): the insured mask depends on the reader’s role. insured_dim shows real birth dates and addresses to any session holding SYSADMIN, and CLAUDE_WS_ROLE holds it. Needed: QA’s operational check (QA standard 4.9) shows that Mary’s connector role does not hold SYSADMIN and reads the mask.

    F-6 (low): the key-declaring hook errors in runs of unit tests alone. Builds and the run-operation declare the keys; only a test run with nothing built errors. Not a data risk.

    F-7 (low): the red runs came after the merge. Recorded in the QA record; the Code Review Standard asks for them in the pull request before review.

    F-8 (medium): Q-11 by policy number is not Q-11 by policy. NF-100005 arrived from Northfield Life with its carrier code and from one Sunbelt Senior sale without one, so the vault keeps two policy records under one number, as designed until release 2’s business vault. Grouped by policy number, agents_named answers 1 agent on 14 policy numbers and 2 on 1; the release page’s card, counting records, says 15 and 1. Needed: the page’s prompt and card agree, in Mary’s words.
