2. Logic areas

Logic area A: client number hard rule and hashing (stg_sunbelt_client)

Dimensions: presence (present, empty string, whitespace only, NULL) and form relative to an existing number (exact, case differs, surrounding spaces, internal form differs). Brute force 4 x 4 = 16. Collapse: form matters only when a value is present (12 combinations reduce to the 4 forms), and exact form is the baseline every other path compares against; empty and whitespace-only behave alike after design decision D-4. Unique paths: surface variant (P4), internal-form variant (P5), NULL (P6), empty or whitespace only (P7).

Logic area B: keep the first sighting (client_h)

Dimensions: arrival (first load only, both loads, second load only), rows per key within one load (one, two), technical key across loads (same, new), hub state (empty first build, incremental build). Brute force 3 x 2 x 2 x 2 = 24. Collapse: the hub ignores the technical key, so both technical-key cases behave alike (24 reduce to 12); a first build and an incremental build differ only in whether existing keys are skipped, which the arrival paths already separate. Unique paths: new key (P1), key in both loads keeps the first (P2, run with a new CRM row ID), key first seen in a later load on an incremental build (P3), two rows of one key in one load (P8).
