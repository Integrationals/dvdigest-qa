Classification Internal — Data Management

1. Quality standard

This profile follows Standard: Profiling (K#10 I#15): field intent, value discipline, and population for every column, and a verdict of Integrate, Defer, or Reject for each, naming its check. It does not redefine the criteria.

2. Data profile

Source ERD

The branch’s source tables as they land, with their real columns: Sunbelt Senior’s client list and policy sales data, Northfield Life’s policy data, Pinecrest Mutual’s policy data for Lab 1-2, and the team’s source system seed. No source declares a relationship to another table’s rows, so every relationship is dashed and carries its match rate, counted in LANDING on 2026-10-26: 10 of the sales data’s 11 client numbers are in the client list (A-1033 is not); 3 of its 9 Northfield policy numbers are in Northfield Life’s data; and of 7 producer numbers across the sources, the sales data’s 5 include 4 found in another source, Northfield Life’s 4 are all found elsewhere, and Pinecrest Mutual’s 6 are all found elsewhere. The agent is an entity no source sends. No landed column refers to the seed; the vault uses its codes as record sources.

2.0 Population context

The rows are the clients of one fictional agency that an insurance distributor has acquired. Load 1 is the agency’s first full extract. Load 2 is a delta: it carries only new clients and rows that changed or reappeared, so a client absent from load 2 has not left the agency. That matters in a later increment, because an effectivity satellite can read absence as departure only from full extracts.

Names are invented and belong to no real person. There is no test data to filter: every unusual row is a scenario written for the course, listed in profile result P-1 with the path it exercises. The base population for every percentage below is the 43 rows.

3. Profile results

Numbered P-1, P-2, … in one series. An anomaly carries SOLUTION NEEDED and closes with RESOLVED, the resolver, the date, and the solution, in that order.

P-1. The eight paths and their rows. The Permutation Coverage Method enumerated five input dimensions (client number presence; form relative to an existing number; arrival across loads; technical key across loads; rows per key within a load): 4 x 4 x 3 x 2 x 2 = 192 combinations, collapsing to 8 distinct behaviors of the staging model and the hub.

Path Input Rows Expected hub behavior
P1 Present number, first load only load 1: A-1001 to A-1030 (30 rows, three of them also P2) new hub row stamped with load 1
P2 Present number in both loads load 2: A-1001 and A-1002 with the same CRM row ID, A-1003 with a new one (3 rows) one hub row; first sighting kept
P3 Present number first seen in load 2 load 2: A-1031, A-1032 (2 rows) new hub row stamped with load 2
P4 Case or surrounding-space variant of an existing number load 2: a-1004, A-1005 with a trailing space (2 rows) same key; no new row
P5 Internal-form variant load 2: A1007, A-01008 (2 rows) a different key; a separate hub row
P6 NULL number load 1 (1 row) all-zeros key; the unknown ghost record; no new row
P7 Empty or whitespace-only number load 1 empty string, load 2 three spaces (2 rows) see P-4
P8 Two rows in one load hashing to one key load 1: a-1010 beside A-1010 (1 extra row) one hub row

Totals: 43 rows; expected hub rows 34 (A-1001 to A-1032 and the two internal-form keys) plus the two ghost records. Check: hub row count equals 36 after the build, and distinct non-ghost keys equal 34.

P-2. Case and surrounding-space variants unify; internal-form variants do not. Rows: a-1004, A-1005 with a trailing space and a-1010 resolve to existing keys; A1007 and A-01008 become new keys. Basis: the toolkit’s hash pipeline (CAST, TRIM, UPPER, removal of line breaks and tabs), read in its code on 2026-10-22. Check: the P4, P5 and P8 unit tests.

P-3. Internal-form variants leave a possible duplicate client. SOLUTION NEEDED. A1007 may be client A-1007 and A-01008 may be A-1008; the vault keeps both as separate keys and cannot tell. This is deliberate and stays open: resolving identity is integration work that later increments address.
